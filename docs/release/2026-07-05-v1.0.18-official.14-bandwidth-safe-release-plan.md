# v1.0.18-official.14 发版带宽保护方案

本文是流程文档和脚本方案，不是执行记录。不要直接复制整段在服务器上运行；发版前必须先由人工确认虚拟机测试通过、Release assets 完整、对象存储/CDN 地址可用。

## 核心结论

- GitHub Actions 打包和上传 Release assets 不占官网服务器带宽。
- `curl --limit-rate 2m` 只能保护“官网服务器从 GitHub 拉包”的同步阶段，不能保护“用户从官网服务器下载大文件”的上线后阶段。
- 700MB+ offline ZIP 不建议由官网服务器直出，优先放对象存储/CDN。
- `download-latest.json` 的 offline ZIP URL 优先指向 CDN；如果 offline ZIP 已放 CDN，不要强行改成 `www.leishen-ai.cn`。
- 官网服务器优先只维护小 JSON、`*-updater.exe`、`*-online.exe` 等必要小文件。

## 目标服务器

```bash
ssh -p 22 -o ServerAliveInterval=10 -o ServerAliveCountMax=6 root@45.207.197.181
```

不要把服务器密码、GitHub token、私钥写入脚本、JSON、Release notes 或日志。

## 资产分流策略

| 资产 | 推荐承载位置 | JSON 规则 |
| --- | --- | --- |
| `latest.json` | 官网服务器 | 只包含 updater |
| `download-latest.json` | 官网服务器 | online 可指向官网；offline ZIP 优先指向 CDN |
| `components.json` | 官网服务器 | 组件 URL 不写凭据 |
| `*-updater.exe` | 官网服务器或 CDN | 可用官网 URL |
| `*-online.exe` | 官网服务器或 CDN | 可用官网 URL |
| `*-windows-x64.zip` | 对象存储/CDN | 不建议官网服务器直出 |

如果临时让官网服务器托管 offline ZIP，必须标记为临时方案，避开高峰期，并准备随时把 `download-latest.json` 的 offline URL 切回 CDN 或隐藏 offline ZIP。

## 同步阶段安全模板

仅当人工确认需要由官网服务器临时下载某个 Release asset 时，才使用下面的模板。禁止并发下载多个 Release assets；禁止无限速 `curl` / `wget` 下载大文件。

默认限速 `2m`，常规最高 `3m`。`6m` 只允许人工确认低峰期且 `/health`、SSH、API 均稳定时临时使用。

```bash
VERSION="v1.0.18-official.14"
BASE="/home/claude-realy-service/public/tools/codex-plus/releases/$VERSION"
FILE="CodexPlusOfficial-1.0.18-official.14-windows-x64-updater.exe"
URL="GitHub下载URL"
EXPECTED_SHA256="填入 Release SHA256"
EXPECTED_SIZE="填入字节大小"

curl -fsS https://www.leishen-ai.cn/health
cd /home/claude-realy-service
docker compose -p claude-realy-service-home ps
docker stats --no-stream

mkdir -p "$BASE/.staging"

curl -fL --retry 10 --retry-delay 10 --retry-all-errors \
  --connect-timeout 15 --speed-time 60 --speed-limit 10240 \
  -C - --limit-rate 2m \
  -o "$BASE/.staging/$FILE" \
  "$URL"

actual_sha256="$(sha256sum "$BASE/.staging/$FILE" | awk '{print $1}')"
actual_size="$(stat -c '%s' "$BASE/.staging/$FILE")"
test "$actual_sha256" = "$EXPECTED_SHA256"
test "$actual_size" = "$EXPECTED_SIZE"

# 仅校验通过后发布到公开目录；失败时不要暴露半成品文件。
mv -f "$BASE/.staging/$FILE" "$BASE/$FILE"

curl -fsS https://www.leishen-ai.cn/health
docker compose -p claude-realy-service-home ps
docker stats --no-stream
```

如果 SSH 卡顿、`/health` 变慢、API 转发受影响、官网下载变慢或 Docker 资源异常，立即停止下载：

```bash
pkill -f 'curl .*CodexPlusOfficial' || true
```

## JSON 生成规则

`latest.json` 只给自动更新用，只包含 updater。`download-latest.json` 给官网下载页用，包含 online 和 offline。`components.json` 给组件下载用。

如果 offline ZIP 已放 CDN，`download-latest.json` 中 ZIP 的 `url` 使用 CDN 地址，不要改成官网服务器地址。

```json
{
  "version": "v1.0.18-official.14",
  "assets": [
    {
      "name": "CodexPlusOfficial-1.0.18-official.14-windows-x64-online.exe",
      "url": "https://www.leishen-ai.cn/tools/codex-plus/releases/v1.0.18-official.14/CodexPlusOfficial-1.0.18-official.14-windows-x64-online.exe",
      "purpose": "installer"
    },
    {
      "name": "CodexPlusOfficial-1.0.18-official.14-windows-x64.zip",
      "url": "https://cdn.example.com/codex-plus/releases/v1.0.18-official.14/CodexPlusOfficial-1.0.18-official.14-windows-x64.zip",
      "purpose": "offline"
    }
  ]
}
```

JSON 中禁止写 GitHub token、服务器密码、私钥。

## latest.json 原地覆盖

如果 `latest.json` 是单文件 bind mount，必须原地覆盖，不要用 `mv` / `os.replace` 换 inode：

```bash
tmp="$(mktemp)"
# 生成 JSON 到 "$tmp"
cat "$tmp" > /home/claude-realy-service/public/tools/codex-plus/latest.json
rm -f "$tmp"
```

不要执行 `./rebuild-and-deploy.sh`，除非人工明确确认。不要直接 `docker compose up -d claude-relay`。

## 上线后验证

`curl -I` 只取响应头，不下载 700MB+ 大文件，是安全验证方式。

```bash
curl -fsSL https://www.leishen-ai.cn/health
curl -fsSL https://www.leishen-ai.cn/tools/codex-plus/latest.json
curl -fsSL https://www.leishen-ai.cn/tools/codex-plus/download-latest.json
curl -fsSL https://www.leishen-ai.cn/tools/codex-plus/components.json
curl -I https://www.leishen-ai.cn/tools/codex-plus/releases/v1.0.18-official.14/CodexPlusOfficial-1.0.18-official.14-windows-x64-updater.exe
curl -I https://www.leishen-ai.cn/tools/codex-plus/releases/v1.0.18-official.14/CodexPlusOfficial-1.0.18-official.14-windows-x64-online.exe
curl -I "download-latest.json 中 offline ZIP 的实际 URL，优先为 CDN 地址"
```

如果 offline ZIP 临时指向官网服务器，发布后要持续观察 `/health`、API 转发、Docker 状态和公网下载页。官网变慢时，优先替换或下线 offline ZIP URL，不要优先重启主服务。
